1. SYSTEM OVERVIEW & ARCHITECTURE
--------------------------------------------------------------------------------
Quarantine Care is an integrated clinical operations platform designed for hospital
isolation units, quarantine wards, and epidemiological field centers. The system
consists of a robust TypeScript Express backend with MongoDB and a modern Next.js 15
(App Router, TypeScript, Tailwind CSS) bedside web frontend.

System Architecture:
- Frontend: Next.js 15 (App Router, React 19, TypeScript, Tailwind CSS, Lucide Icons)
- Backend: Node.js, Express, TypeScript (Strict Mode)
- Database: MongoDB Atlas (with local MongoDB fallback) via Mongoose ODM
- Authentication: Lightweight header-based authentication via `x-staff-id`
- Authorization: Role-based route guards (Nurse, Doctor, Admin)
- Clinical Workflow Gates:
  * Duplicate vital log prevention (409 Conflict) with `?force=true` override.
  * Prerequisite vital enforcement (400 Bad Request if doctor logs visit without vitals).
  * 3 consecutive fever-free days quarantine release protocol.
  * Epidemic mortality alert banner (>15% mortality threshold).

3. USER FLOWS & WORKFLOW SPECIFICATIONS
--------------------------------------------------------------------------------

A. Authentication & Route Guard Flow:
1. User opens http://localhost:3000 -> redirected to /login.
2. User enters Staff ID (e.g. "N001") or clicks a quick-access pill.
3. Client POSTs to `/api/login`, returns `{ staffId: "N001", name: "Nurse Sarah Jenkins", role: "nurse" }`.
4. AuthContext persists profile in `localStorage` under `quarantine_care_staff`.
5. User is redirected to `/nurse` (or `/doctor` for D001, `/admin` for A001).
6. If a Nurse manually enters `/admin` in the browser URL:
   - `RoleGuard` detects role mismatch (`nurse` != `admin`).
   - `RoleGuard` redirects user back to `/nurse`.
   - Toast notification appears: "Not authorized for this view."

B. Nurse Bedside Vitals Workflow:
1. Nurse opens `/nurse`.
2. Active patient list loads with `tempLoggedToday` badges (Recorded vs Vitals Needed).
3. Nurse clicks a patient card -> opens bedside detail modal.
4. Nurse inputs temperature (e.g. 98.6°F) and clicks "Save Vitals".
5. If already logged today:
   - Backend returns `409 Conflict` with `existingLogTime`.
   - Frontend displays confirmation modal: "Already logged today at [time]. Overwrite?"
   - On confirmation, re-submits with `?force=true`.

C. Doctor Rounds & Discharge Workflow:
1. Doctor opens `/doctor`.
2. Patients needing rounds ("Not Visited Today") are highlighted first.
3. Doctor selects a patient and inputs clinical consultation notes.
4. If temperature has not yet been recorded for today:
   - Backend returns `400 Bad Request`: "Cannot log visit: temperature not yet recorded today".
   - Frontend shows inline warning banner with exact backend message.
5. If temperature was recorded today:
   - Visit is saved with timestamp and doctor ID.
6. When a patient reaches 3 consecutive fever-free days:
   - "Discharge Ready" badge appears.
   - Doctor clicks "Discharge Patient" -> confirmation dialog -> approves discharge.
7. If patient succumbs to illness:
   - Doctor clicks "Deceased" -> high-friction confirmation dialog requiring clinical notes -> marks status as deceased.

D. Administrator Operations Workflow:
1. Admin opens `/admin`.
2. Evaluates 74-bed facility occupancy rate and throughput.
3. Reviews mortality rate against the 85.0% success benchmark.
4. If mortality exceeds 15.0%:
   - Prominent red epidemic alert banner pulses across the top of the screen.
5. Reviews the Discharge Queue table showing all patients eligible for discharge.
